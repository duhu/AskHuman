# 手动暂停与恢复 AskHuman 接管

## 已确认的体验

2026-11-02 用户选择：本机全局手动暂停 / 恢复；日常主要使用 Codex 桌面 App 与 Claude Code。
在电脑前可以直接使用 Agent 原生对话，离开时恢复 AskHuman 的既有渠道。

- 菜单栏提供「暂停接管 / 恢复接管」，作答窗口顶部也能暂停整台电脑的接管。
- 暂停不停止 Agent 的工作、不删除集成或渠道配置，不影响其他电脑。
- 普通提问、完成报告与下一任务交接回到 Agent 原生对话；不自动出队执行待办。
- 权限确认回到 Agent 原生审批，暂停不构成允许、拒绝或任何人类答案；Stop 不再额外拦截。
- 已在等待的请求在客户端检测到暂停后释放，连接关闭使 daemon 收尾弹窗、IM 与手机请求。
  普通文本调用返回明确的模式变更及原始题目；内部 JSON Hook 不生成答案，由适配器回到原生流程。
- 恢复后沿用原有渠道。已交回 Agent 的问题不重新推送；恢复不主动启动或续跑 Agent。
- 状态持久化，重启后仍然暂停；需要用户手动恢复，不做空闲检测或自动切换。

## 实现边界

`interaction_control.rs` 将状态原子写到当前实例 `state/interaction-control.json`。
私有 Dev Instance 使用自己的状态，不修改日常正式端。每次暂停生成一个 epoch；即使两次轮询间
用户已经恢复，旧等待者仍要释放。客户端轮询间隔 100 ms；协调器拒绝暂停或 epoch 已变化后的
迟到作答，避免待办出队与权限记忆副作用。

CLI `interaction status|pause|resume` 和 GUI 写同一状态，不依赖 daemon 存活，不改 IPC 线上形态。
`run_ask_final_async` 与 `run_confirm` 共同负责暂停前检查与在途连接释放。
Codex App 原生请求桥也遵守暂停：不新建作答面，取消已经转送的等待，恢复不重接旧原生问题。
权限 Hook 在权限记忆 / 自动允许判断前检查暂停。生命周期跟踪、历史查询与待办管理继续保留。

Codex / Claude 的 mode-owned 恢复 Hook 新增 `UserPromptSubmit` 状态提示，CLI / MCP 模式都安装，
不依赖可关闭的生命周期。Codex 保留原有信任维护与委派运行静默边界。已有集成需显式更新受管
产物；已有 MCP 连接的 schema / 说明仍需重连刷新。提示词明确将用户暂停作为交互协议的例外。
其他 Agent 的 CLI / MCP 请求同样受运行时暂停保护；没有 per-turn Hook 的客户端在下一次需要
交互时通过一次正常 AskHuman 调用刷新状态。不能保证所有客户端都重新显示原生选择控件，普通
问题由 Agent 根据回执在原对话重述。

## 验证

- 状态持久化、重复写入、暂停后快速恢复、暂停时不执行工作 future。
- Hook 安装 / 更新 / 移除、Codex 信任与委派静默，以及暂停 / 恢复提示。
- 暂停前已提交与暂停后新提交的 CLI / MCP 调用、权限原生回退、待办不出队。
- 菜单栏状态、恢复入口、作答窗口暂停按钮；真实 Codex App / Claude 原对话的表现需要实际会话验收，
  不以合成 IPC 或单元测试冒充。真实模型调用仍需用户单独授权。
